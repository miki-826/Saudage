## ゲーム契約

Memory ID: `store`, `stocking`, `service`, `complaint`, `regular`。

1. Analysis Engineの返すのは関連記憶・関連性・ヒント強度・証拠深度・関与・進めるべきかのみ。
2. 本番会話は毎回AIが意味の近さを判定する。完全一致・番号・親子順序は不要。未解放の5記憶から発言に最も近い1件を選び、shouldAdvanceかつ関連度0.65以上ならMemory Engineが即時100%・解放にする。例:「箱から出して陳列」はstocking、「毎朝同じ飲み物を買う顔なじみ」はregular。
3. AI障害時だけ、明確なキーワードを代替判定し通知する。近い意味をAIで判断できたとは扱わない。無関係・低関連・解放済みの記憶では解放しない。
4. Stageは進捗20未満=0、20以上=1、50以上=2、解放=3。
5. NFKCと句読点空白の正規化後に同一発言なら進捗なし。直近100発言を保持。
6. `store/stocking/service/complaint/regular` の5つがすべて解放されたらクリア。4つでは終了しない。
7. 人格指標は進捗平均、感情記憶、会話数、常連記憶から計算。数値をプレイヤーに直接見せず、話し方・色味・段階名で示す。
8. 音声接続後または最初の文字送信後、進展のない会話画面で30秒ごとに短いヒントを最大3段階表示・発話。発話中・処理中は待ち、モーダル・解放演出・非表示タブでは計時を停止。進展時は計時とヒント段階をリセット。時間だけで記憶は開かず、旧 `/api/memory` の `action:reveal` も拒否する。
9. 音声・文字とも質問や回答の催促をしない。感覚や気づきで応じ、無関係な話題は現在の手がかりへ戻す。右下に「会話を終了して抜ける」を配置し、退出時は音声・カメラ・待機中の発言を停止。
10. BGMは初期オン。自動再生がブラウザーに制限される場合は最初のクリック・キー操作で再生。説明文を拡大し、最初の紹介カード右側の装飾マークは削除。

解析用モデルには正解を含むストーリーを送るが、キャラクター用モデルには解放された事実・段階に応じた断片・現在の曖昧なヒントだけを渡す。
音声モデルは自分でゲーム状態を更新しない。プロンプトによるネタバレ抑制はあるが、生成内容が必ず制約に従うことは保証しない。サーバーの進捗は生成発言に依存せずMemory Engineが決める。
ストーリーJSONの変更で文章・関連性を変更できる。Memory ID/個数を変える際は解析schema、状態schema、クリア条件、テストも合わせて変更する必要がある。

## API

| ルート              | 入出力・処理                                                                        |
| ------------------- | ----------------------------------------------------------------------------------- |
| GET `/api/config`   | AI/クラウド/コード要求の有無だけ。秘密値なし、no-store                              |
| POST `/api/session` | `action:new/load/save`, 任意token/mode。端末Cookie作成、セーブ読込・クラウド保存    |
| POST `/api/analyze` | 署名token、発言、任意の数値特徴。解析→Memory Engine→応答→新token。一括処理          |
| POST `/api/memory`  | 検証済tokenから現在の状態・人格・許される記憶を取得。外部から得点を受け取らない     |
| POST `/api/live`    | 検証済tokenとSDP。サーバーのキーで `/v1/live/sessions` に接続しSDP answerだけを返す |

Zodで入力検証。無効なtoken・他端末のtoken・クロスオリジンPOSTを拒否。AIエラーはキーを含めずユーザー向け文面に変換。解析失敗時はキーワード判定にフォールバックして会話を止めない（通知を表示）。テキスト応答のみ失敗した場合は記憶更新を保持し、用意した台詞と通知を表示。
APIエラーの詳細本文、音声、カメラ映像をアプリログに出さない。

## 音声・カメラ

- GPT-Liveモデル既定 `gpt-live-1`。音声 `marin`。SDP作成前にイベントチャネルとマイクを登録。ICE待機（最大3秒、未完了でも送信）後サーバーへ送信。`session.start` はデータチャネルに送らない。
- **delegation は `responses`**（バックエンドモデル既定 `gpt-5.6-luna`）。client delegationはアプリが結果を返さない限りGPT-Liveが待ち続け、会話が止まる。会話の判定はアプリの `/api/analyze` が独立して行うため、client delegationは使わない。
- セッションの `instructions` は発話レイヤー（`voicePrompt`）、`delegation.responses.instructions` は人格レイヤー（`characterPrompt`）。
- `session.started` 後に会話開始。`session.input_transcript.delta` を1.1秒の静止、または7秒の上限でまとめて解析へ渡す。入力イベントにターン完了通知がないため、これはアプリ側の区切り方。`end_ms` は近似値なので重複判定には使わない（使うと発話が欠落する）。
- 出力字幕は `start_ms` の間隔が1.4秒を超えたら新しい発話として区切る。区切らないと過去の返答が連結して読めなくなる。
- Memory Engineの結果は `session.update` の `delegation.responses.instructions` で**置換**する。`session.instructions.append` を積み重ねると文脈が膨らみ、同じ返答を繰り返す原因になる。解放時のみ `session.commentary.append` で反応を促す。
- 解放演出中はマイクと再生をミュートし、閉じると再開。タブ非表示ではマイクをミュートするだけで接続は維持する。
- `session.closed`（`expired` / `connection_lost`）と文脈使用率85%超で最大2回まで自動再接続。ホーム移動と終了操作で `session.close`。
- マイクは `checkMicrophone()` で事前判定し、拒否・非対応・未検出なら選択肢とテキストへ自動で切り替えて理由を画面内に表示する。
- 映像は送信しない。約6fpsで端末内処理。送る特徴はsmileDelta / headMovement / eyeMovement / mouthMovement。感情の診断に使用しない。
- カメラ拒否・故障でも文字会話は継続。カメラ/マイクはページ読み込み時には要求しない。

## 保存・権限

- セーブはversion 1。UUID、端末owner hash、mode、記憶配列、会話数、直近発言、直近16件（合計文字数も制限）の履歴、時刻、完了フラグ。
- HMAC SHA-256署名tokenをlocalStorageへ会話ごとに保存。署名キーは `SESSION_SECRET`、未設定時はサーバーのOpenAIキー。両方なければ開発専用キー。本番で両方なければ503。
- 端末識別はhttpOnly/SameSite=Lax/本番Secure Cookie。tokenは端末hashに紐づく。暗号化ではなく改ざん検知。端末内の会話データは読むことができる。
- Supabase任意。service_roleはサーバーのみ。RLS有効、anon/authenticatedにテーブルや保存RPC権限を与えない。RPCで3テーブルを同一トランザクションに保存。
- クラウドは保存ボタンで更新。端末tokenがなければ同じCookieの最新クラウドセーブを検索できる。
- ログイン/端末間同期は対象外。Cookie・署名キーが変われば旧セーブを読み込めない。
- `GAME_ACCESS_CODE` 任意。AI有料エンドポイントに適用。コードは設定画面から入力し、永続化しない。
- 簡易レート制限はサーバーインスタンス単位。分散環境の強固な制限、リプレイ防止、同時タブ間の競合解決は未実装。競争型ゲームや不特定多数への大規模公開には共有ストア等の拡張が必要。
